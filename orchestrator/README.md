# orchestrator

The research lead of the Softmax IDE: the profile the user talks to. It turns the user's
requests into Goals and Tasks, answers the Researchers' questions, reviews their work, makes and
submits policy Versions. The lifetime `research serve` coordinator keeps background work moving. Its principles are the design's: the user's explicit request comes first and is
never refused, agents repair what breaks and keep going, and the few gates that exist bound only
the agents' own initiative.

Everything it does lives in the shared package [`core/`](../core/README.md). This folder is the
Hermes distribution shell:

| File | What it is |
|---|---|
| `distribution.yaml` | The manifest: the variables `.env` must define (`env_requires`) and what the profile is. |
| `config.yaml` | The shipped Hermes config: the default model (`moonshotai/kimi-k3.1-pro`, falling back to `z-ai/glm-5.3`; Kimi pinned to Moonshot's endpoint; the user changes it through the bridge), approvals off, no deny list, memory off, the `orchestrator` plugin and the `ide-orchestrator` toolset, the compaction settings that keep the user's instructions word for word, pruning of old large tool results from 64,000 tokens, the Hermes `browser`, `connections` and `cronjob` toolsets off, the terminal environment passthrough (without `SOFTMAX_USER_CREDENTIAL`). |
| `SOUL.md` | The system prompt, generated by `uv run python tools/build_prompts.py --write` from `core/src/research_core/prompts/`; do not edit by hand. |
| `plugins/orchestrator/` | The plugin entry (`plugin.yaml` lists the tools; `__init__.py` imports `research_core` from the path in `local/core-path.txt`). |
| `scripts/prepare.py` | Preparation after install or update; see below. |
| `cron/jobs.json` | No shipped cron jobs; observation belongs to `research serve`. |
| `.no-bundled-skills` | Hermes installs only its essential `hermes-agent` skill; the profile's other skills come from `core/src/research_core/skills/` through `skills.external_dirs`. |
| `local/` | Written at preparation (`core-path.txt`, `workspace-shell.sh`); not shipped. The prepared marker is `.softmax-prepared` in the profile home. |

## Tools

24 tools, listed in `plugins/orchestrator/plugin.yaml`. `SOUL.md` lists their actions; the
`briefing` prompt section is a snapshot of the session Coworld's state, written when Hermes builds
the Session's prompt and then replayed with it (`core/src/research_core/plugin/briefing.py` says
what renders it again).

## Install

```bash
hermes profile install ~/ide-distributions/orchestrator --name orchestrator --yes
# write ~/.hermes/profiles/orchestrator/.env (see distribution.yaml env_requires)
<hermes python> ~/.hermes/profiles/orchestrator/scripts/prepare.py \
  --source ~/ide-distributions/orchestrator --hermes $(command -v hermes)
```

`prepare.py` records where the shared code lives, creates the stores, re-applies the config
keys the machinery relies on, points the profile at the shared skills and every registered Coworld's code,
moves open chats onto a release's changed tools and instructions, builds the workspace environment under `$IDE_WORKSPACE/tools/venv`, and retires the obsolete watcher cron. Run it again after every `hermes profile update`;
`--check` shows what it would change. `docs/hosting.md` has the full contract.

## The watcher

`research serve` owns observation and domain transitions. Its periodic workflow includes store checks, champion
sync, resolved waits, run recovery, Researcher messages, merges of accepted work, Goal
bookkeeping, capability checks, Task dispatch, wakes (setup, review, management, anti-stall
Sessions of this profile), the heartbeat and the agent-context panel. `research watcher status`
prints the last tick; `workspace.doctor` reports it to the agent.
